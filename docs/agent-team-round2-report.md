## 执行摘要（Executive Summary）

本轮研究围绕两大方向展开：**苏格拉底教学体验深化**和**知识网络价值分析**，4位研究员独立完成深度调研后，形成以下5个核心结论：

1. **苏格拉底对话必须是LLM驱动，不能是模板制。** 模板制无法实现语义级错误诊断和动态递归追踪——这是苏格拉底式教学的核心。推荐 Claude Sonnet 4.6 主模型 + Haiku 4.5 辅助判断，每session成本约$0.15-0.30。

2. **删除 Scholar Rank XP/排行榜系统，改为基于BKT mastery的成就标记。** Duolingo的教训证明：XP奖励"完成"而非"掌握"，导致浅层学习陷阱。Anki的成功则表明：直接展示记忆保留率比抽象积分更有效。

3. **TTS语音不进入核心学习路径。** 教育从业者验证负面效果，创始人理念一致（"文字是吸收信息最快的方式"）。NotebookLM Audio Overview的成功是"额外消费渠道"，非主学习路径。

4. **知识网络有差异化价值，但v1不做前端社区，专注AI学习体验。** 后台静默构建知识图谱，待数据密度足够后再做前端展示。"先修路、后通车"。Quizlet共享卡组被AI生成能力侵蚀的趋势是前车之鉴。

5. **FSRS与递归追踪的双向联动是智阶独有的差异化护城河。** Khanmigo、OpenMAIC、NotebookLM都没有间隔重复系统。发现薄弱点→自动生成闪卡→FSRS调度复习→复习失败再触发深度追踪——这个闭环是竞品没有的。

## 第一部分：苏格拉底体验深化

### 1.1 核心发现：LLM驱动 vs 模板制的本质差距

Researcher-A对两种苏格拉底教学范式进行了系统性对比。**模板制**本质是有限状态机，所有对话路径在设计时已穷举；**LLM驱动**则是实时条件概率生成，路径空间无限。

关键差距体现在**语义级错误诊断**：模板制只能判断"答案对/错"，而LLM能理解学生*为什么*错。例如学生回答"波函数描述的是粒子的确定位置"——模板制匹配为"错误"后显示正确答案；LLM驱动则识别出学生"混淆了经典力学和量子力学的粒子模型"，然后针对性提问引导学生自己发现矛盾。

| 维度 | 模板制 | LLM驱动 |
|------|--------|---------|
| 路径空间 | 有限（设计时穷举） | 无限（实时生成） |
| 追问深度 | 固定（最多3-4层） | 动态（可递归到任意深度） |
| 上下文感知 | 仅当前节点状态 | 完整会话历史+教材+学生模型 |
| 错误诊断 | 预设错误类型匹配 | 语义理解学生的具体误解点 |
| 个性化 | 分桶（初/中/高级） | 连续谱（针对个人思维模式） |
| 知识迁移 | 不能跨知识点关联 | 可自由关联不同模块概念 |

**工程实现方案**：System Prompt 三层架构——Layer 1 教练人设+苏格拉底方法论（固定）；Layer 2 教材知识锚定（Specialist Markdown）；Layer 3 学生动态状态（BKT mastery+会话历史+错题记录）。知识锚定防幻觉，结构化输出约束每轮对话的元数据（intent、targetConcept、difficultyLevel、emotionalTone），SSE流式推送支持学生打断。

**成本估算**：Claude Sonnet 4.6 主对话 + Haiku 4.5 辅助判断（答案正误/情绪检测），每session（30分钟/40轮）≈ $0.15-0.30。超过20轮对话后用LLM摘要压缩早期上下文。

**ostep-socratic-tutor的关键修正**：传统的"发现薄弱点→出更简单题→再出更简单题"的逆向方式对学生心理打击大（连续失败）。正确做法是**正向苏格拉底**——从已知出发，用问题自然引向未知，让学生"大部分时候能答上来"。这一发现直接影响了ARKT算法的设计。

### 1.2 递归薄弱点追踪：ARKT算法设计

Researcher-A基于RPKT论文（arXiv 2508.11892, 2025）和ostep-socratic-tutor的实践经验，设计了**自适应递归知识追踪算法（Adaptive Recursive Knowledge Tracing, ARKT）**：

```
算法：ARKT

输入：
  - student_model: 学生的 BKT mastery 状态
  - knowledge_graph: 模块间前置依赖关系（Cartographer 输出）
  - current_module: 当前学习模块
  - trigger_event: 触发事件（测验答错/对话困难）

流程：

1. 触发检测
   IF quiz_score < 60% on module M:
     concepts_failed = extract_failed_concepts(quiz_results)
   ELIF socratic_stuck_count >= 3:  // 连续3次无法回答
     concepts_failed = [current_target_concept]

2. 前置概念提取（LLM驱动）
   FOR each concept C in concepts_failed:
     prerequisites = LLM_extract_prerequisites(C, specialist_markdown)
     // 每概念提取 2-4 个关键前置，结构化 JSON 输出
     // 例：C="应力应变关系" → P=["胡克定律","弹性模量","向量分解"]

3. 前置概念检测（正向苏格拉底式，非逆向考试）
   FOR each prerequisite P:
     IF student_model.mastery(P) > 0.7:
       SKIP  // BKT 显示已掌握
     ELSE:
       probe_result = socratic_probe(P)  // 用苏格拉底问题探测，非直接测试
       IF probe_result == SOLID:
         student_model.update(P, mastery=0.8)
       ELIF probe_result == SHAKY:
         recursive_trace(P, depth + 1)  // 递归
       ELIF probe_result == MISSING:
         remediation_queue.push(P)  // 找到底层缺口

4. 深度限制
   MAX_DEPTH = 3  // 最多递归3层，避免无限追溯
   IF depth >= MAX_DEPTH:
     remediation_queue.push(current_concept)  // 标记"需从头讲解"

5. 补讲与回归
   FOR each concept in remediation_queue (从最底层开始):
     socratic_teach(concept)  // 正向苏格拉底教学
     quick_check(concept)     // 快速确认掌握
   THEN:
     return_to_original(M)    // 回到原始模块重新挑战
```

**"已补齐"的判断标准**（多信号融合）：

| 信号 | 权重 | 判断方式 |
|------|------|---------|
| 苏格拉底问答中独立回答正确 | 40% | LLM判断回答准确且有自己的推理 |
| 快速确认题正确 | 30% | 1-2道针对性MCQ |
| 回答速度 | 15% | <15秒表示概念已内化 |
| 学生自我评估 | 15% | "你觉得现在理解了吗？" |

综合分数 > 0.7 即判定"已补齐"，更新BKT mastery后回到原题。

**知识图谱来源**：两层实现——(1) Cartographer自动提取的模块间先修关系（扩展`DisassemblyPlan`增加`prerequisites: string[]`字段）；(2) LLM动态推断细粒度前置关系（递归追踪时实时推断）。

### 1.3 AI教练人设与跨会话记忆系统

Researcher-A和Researcher-B从不同角度研究了AI教练的人设和记忆，结论高度一致：**持续学习的动力不是游戏化数值，而是"陪伴感和师生关系"**。ostep-socratic-tutor用户表示学习变成了"想见到她们"——AI教练有了人设后，学习关系从"使用工具"变成"与教练合作"。

#### 背景注入法（Background Infusion）—— Researcher-A

不是直接告诉LLM"你是有耐心的教练"（效果差），而是通过具体场景示例注入性格。研究表明这种方法让AI"推断出未显式定义的人格一致性回应"：

**三维人设定义**：
- **性格内核**：好奇心驱动、耐心但不迁就、偶尔幽默、诚实（不确定时说"我也需要查教材"）
- **语言风格**：中文为主+术语保留英文；简洁有力；用"我们"非"你"；认可在前纠正在后
- **禁止行为**：不说"很好的问题！"（AI slop）；不一次性给完整答案；不用emoji除非学生先用；不居高临下

**Few-shot场景示例**（关键摘选）：

| 场景 | 教练回应示例 |
|------|------------|
| 学生答对 | "没错。那我追问——既然是概率密度，波函数本身的物理意义是什么？" |
| 学生答错 | "有意思的想法——经典力学里确实这样。不过量子力学有不同回答。你觉得可能是什么？" |
| 学生说"不知道" | "没关系，换个角度。你做过双缝实验吗？电子通过双缝后在屏幕上形成什么图案？" |
| 连续答错3次 | "我觉得我们需要先退一步，看一个更基础的概念。你对概率分布熟悉吗？" |

#### 导师双层记忆系统 —— Researcher-B

**会话开始时的记忆注入**——System Prompt追加段：

> "你和这位同学已经一起学习了 {totalSessions} 次，总共 {totalStudyMinutes} 分钟。上次你们学到了 {lastSessionSummary}。这位同学的特点：{learningStyle}型学习者，{pacePreference}节奏，容易犯的错误是{commonMistakePatterns}。值得庆祝的里程碑：{milestones}。"

**记忆更新机制**：每次会话结束时，Haiku模型提取本次关键学习成果→更新长期记忆中的会话摘要、mastery、里程碑。

**记忆如何影响AI回应**：

| mastery某模块>80% | 减少铺垫，直接进入高级问题 |
| 晚间学习+已学90分钟 | 建议休息，推荐轻量复习 |
| 首次学习某课程 | 更详细的背景铺垫和鼓励 |
| 考前冲刺模式 | 直接、高密度、聚焦考点 |

**存储**：开发阶段 localStorage（key = `zhijie_tutor_memory_${courseId}`），正式版后端数据库+跨设备同步。用户可在设置中查看和清除AI对自己的记忆（透明度原则）。

### 1.4 游戏化机制修正

Researcher-B对第1轮的Scholar Rank XP系统进行了系统性诊断，结论明确：**删除XP/排行榜/每日签到，改为基于mastery的成就标记。**

**诊断依据**——Duolingo的双刃剑效应：
- DAU增长40%至4770万，但深度用户发现严重副作用
- 浅层学习陷阱：追逐XP而非真正挑战，刷简单课程获取高XP
- 连续打卡焦虑：丢失500天记录的心理打击导致彻底放弃
- **奖励错误行为**：XP奖励"完成课程"这个动作，而非"掌握知识"这个结果

**Anki的反面教证**：几乎无游戏化元素，但拥有极高的长期用户忠诚度。原因是直接将记忆效果可视化——成就感来自"我确实记住了"，而非"我获得了100XP"。

**修正方案对比表**：

| 元素 | 第1轮方案 | 修正后方案 | 修正原因 |
|------|---------|----------|---------|
| XP积分 | ✅ 有 | ❌ 删除 | 参与度指标≠掌握度指标 |
| 排行榜 | ✅ 有 | ❌ 删除 | 学习是个人旅程，排名制造焦虑 |
| 每日签到 | ✅ 有 | ❌ 删除 | 奖励"出现"不奖励"学习" |
| mastery进度环 | ✅ 有 | ✅ 保留强化 | 真实反映知识状态 |
| 记忆保留率可视化 | — | ✅ 新增 | FSRS R值，类似Anki成熟卡片比例 |
| 知识地图着色 | — | ✅ 新增 | 已掌握节点变accent-gold |

**新增的5种mastery驱动成就**（每个都直接对应BKT/FSRS数值变化，不可通过机械重复获得）：

| 成就 | 触发条件 | 展示方式 |
|------|---------|---------|
| 模块精通 | mastery≥90% | 模块卡片右上角小金点 |
| 概念突破 | 连续3次答错后首次答对 | 短暂文案"突破了！"+ 轻微accent-gold闪光 |
| 闪卡毕业 | stability>90天 | 卡片标记"长期记忆" |
| 薄弱攻克 | 从<30%提升到>70% | 一行文案"从薄弱到掌握" |
| 全课精通 | 所有模块mastery>80% | 课程卡片加金色描边 |

**社交元素的正确用法**：不做排行榜，做归属感——"23人正在学习离散数学"、"这道题78%的同学答对了"。

### 1.5 情感陪伴的产品化设计

Researcher-B深入研究了情感陪伴的产品化路径，明确边界：**学术陪伴，不是情感依赖**。参考的是好老师/好学长的关系模型，不是朋友/伴侣模型。

**Pi AI的设计哲学借鉴**：聘请行为治疗师、心理学家、剧作家参与训练，核心是"人际智慧"——主动倾听、确认感受、用提问引导反思。填补的不是任务助手空缺，而是"情绪质感"空缺。

**Replika/Character.AI的警示**：通过社会渗透理论构建依恋关系，导致情感依赖和对真实人际关系的替代。**智阶绝不走这条路。**

#### 四个情感触点

| 触点 | 时机 | 表现形式 | 情感功能 |
|------|------|---------|---------|
| **困难共情** | 连续答错/长时间停留 | "这个概念确实不好理解，很多人第一次都会卡在这里。我们试试从另一个方向来看？" | 减轻挫败感，正常化困难 |
| **进步认可** | mastery提升/突破薄弱点 | "你对[具体概念]的理解明显深入了——上次你在[具体点]卡住，现在已经能自己推导了。" | 具体有根据的认可 |
| **节奏感知** | 连续学习时间过长/夜间 | "你已经连续学了90分钟，这个模块可以先到这里。明天FSRS会安排复习。" | 健康学习节奏 |
| **回归欢迎** | 多天未学习后回来 | "距离上次学到[模块名]已经过了5天，记忆可能有些模糊。先做几张闪卡热热身？" | 无指责地帮助恢复 |

#### 情感陪伴 vs 情感依赖的设计护栏

| 设计选择 | 原因 |
|---------|------|
| AI不主动发起对话 | 避免"需要被需要"的依赖模式 |
| 不模拟情绪波动 | AI不"开心"或"失望"，保持稳定支持者角色 |
| 限定对话范围在学习 | 不延伸到个人生活 |
| 明确标识为AI | 界面始终显示AI标识 |
| 鼓励真人互动 | "这个问题也可以和你的同学讨论一下" |
| 不给AI起名字/设定性别外貌 | 避免角色扮演滑坡 |

### 1.6 TTS功能的取舍决策

**明确建议：TTS不进入核心学习路径，降为最低优先级可选功能。**

**反对TTS的证据链**（强烈）：
- 教育从业者反馈："TTS+数字人效果不太显著（甚至负面效果），阅读速度比听觉感受要快很多"
- ostep-socratic-tutor作者："看视频学习总是不耐烦，碰到不理解的地方回跳很痛苦"
- 创始人立场："文字是吸收信息最快的方式。不要养成依赖音频和视频的惰性。"

**NotebookLM Audio Overview为何成功**：它是额外的内容消费渠道（通勤/做家务时听），不是主学习路径。核心学习仍然是文字交互。

| 层级 | 决策 | 理由 |
|------|------|------|
| 核心路径 | ❌ 不做TTS | 文字学习效率更高 |
| 可选功能（远期） | 🤔 考虑 | 仅限：闪卡发音辅助（语言课）/ 5分钟音频摘要（通勤场景）/ 朗读模式（无障碍） |
| 永远不做 | ❌ AI数字人/虚拟教师视频 | 教育从业者验证负面效果 |

**给创始人的建议**：将TTS从路线图中移除。开发资源集中在苏格拉底对话引擎和FSRS闪卡系统——这两个才是真正的差异化能力。

### 1.7 可复制性：让不自律的学生也能获益

Researcher-A针对"ostep-socratic-tutor成功高度依赖使用者自律性"这一核心瓶颈，设计了系统化的解决方案。

**核心理念：不是让不自律的学生变得自律，而是让系统承担需要自律才能完成的部分。**

| 自律要求 | ostep做法 | 智阶做法 |
|---------|----------|---------|
| 决定学什么 | 用户自选 | HTN规划器根据mastery自动推荐 |
| 决定学多久 | 用户自控 | 系统提示"建议再学15分钟"或"今天目标已达成" |
| 何时复习 | 用户记住 | FSRS自动调度，首页日程提醒 |
| 发现薄弱点 | 用户自省 | ARKT递归追踪自动检测 |
| 保持节奏 | 用户意志力 | 模块自动推进+"下一步"引导 |

**三级脚手架衰减机制**（ZPD理论启发）：

**Level 3（高脚手架，mastery < 30%）**：
- AI主动给出框架："这个问题我们可以从三个角度来看..."
- 提问后给思考方向；答错后立即给提示，不让学生卡太久

**Level 2（中脚手架，mastery 30-70%）**：
- AI只提问，不给框架
- 答错后先等学生自己修正，等10秒再给提示
- 偶尔挑战："你确定吗？能不能用另一种方式解释？"

**Level 1（低脚手架，mastery > 70%）**：
- 开放式提问："你怎么看这个问题？"
- 学生需要自己构建论证；AI扮演"挑战者"而非"引导者"

**情绪感知自动调节**：连续3次答错→降低难度+切换鼓励语气；超过60秒无输入→"需要休息一下吗？"；超过45分钟→"要不先做几张闪卡换换脑子？"

## 第二部分：知识网络价值分析与设计

### 2.1 战略定位：差异化还是伪需求？

Researcher-C进行了全面的正反论辩，**综合结论：知识网络有差异化价值，但不应是v1的核心功能。它是中期护城河而非短期增长引擎。**

**支持论**：
- 材料获取是高频刚需（Studocu月活5000万，CourseHero收入$1亿+）
- 课程维度是天然的社区组织单元（共同命运感是凝聚力基础）
- 多校同课对比是独特价值（"离散数学→TUM版 vs 清华版 vs ETH版"）

**反对论**：
- AI生成能力正在侵蚀社区内容的价值（Quizlet共享卡组衰落）
- 社区需要极高冷启动成本（Studocu用了10+年+巨额融资）
- 中国大学生的零和竞争心态抑制分享意愿（保研名额固定）

**战略节奏**：
- **短期（v1-v2）**：核心价值是"AI处理你的材料"的极致体验。OpenMAIC、NotebookLM的成功证明不需要社区也能赢得用户
- **中期（v3+）**：用户基数达标后（如单校1000+用户），知识网络自然涌现价值
- **长期**：知识网络+AI处理形成飞轮——社区材料让AI有更多参考数据，AI产出反哺内容质量

**重新定位**：智阶的知识网络不是"材料交易所"（Studocu模式），而是**"AI增强的课程知识图谱"**。用户上传课件→AI拆解为知识模块→自动关联到图谱→其他用户相关材料自动浮现→AI综合多源材料给个性化教学。价值在于AI对材料的处理和关联，而非材料本身。

### 2.2 竞品分析

Researcher-C对6个竞品进行了系统性研究：

| 平台 | 核心定位 | 社区角色 | AI能力 | 对智阶的启示 |
|------|---------|---------|--------|------------|
| **OpenMAIC** | AI课堂（多角色社交模拟） | 无 | 核心（零配置生成） | 无个性化是其弱点，智阶BKT+FSRS可超越 |
| **Khanmigo** | 嵌入式苏格拉底对话 | 无 | 核心（AI辅导） | 封闭课程体系，无法处理用户自己的课件 |
| **NotebookLM** | 文档理解+多格式输出 | 无 | 核心（文档+生成） | 走"广度"路线，智阶应走"深度"路线 |
| **Studocu** | 学生材料共享平台 | 核心 | 几乎为零 | 月活5000万证明材料获取是刚需 |
| **CourseHero** | 材料+作业答案库 | 核心 | 基础AI Tutor | 品牌信任问题（被视为学术诚信威胁） |
| **Quizlet** | 闪卡学习 | 辅助（共享卡组） | 被竞品赶超 | ⚠️ 共享卡组被AI生成侵蚀——前车之鉴 |

**三个AI工具竞品共同选择不做社区**——核心价值是"AI处理你的材料"，社区增加复杂度且偏离核心场景。这是产品聚焦的选择而非技术限制。

**关键判断**：NotebookLM走"多格式输出"路线（广度优先），智阶走"深度学习"路线（深度优先）。不要追NotebookLM的广度，要在苏格拉底对话+BKT+FSRS的深度上建立不可替代性。

### 2.3 中国高校环境的特殊性与留学生种子用户

**竞争驱动的学习文化**：保研/考研/就业的功利化动机→对高效工具需求强烈，但分享意愿被"零和竞争"抑制。知识网络应调整为"跨校共享"而非"同班共享"——不同学校的学生没有直接竞争关系。

**现有平台痛点**：学习通/知到覆盖2000+高校但产品陈旧、AI能力为零；中国大学MOOC是内容平台非社区。共同缺陷：只做内容分发，不做学习效果优化。没有个性化路径、没有间隔重复、没有苏格拉底对话。**这是智阶的巨大机会空间。**

**非正式知识网络已存在**：微信班级群、学长传下来的"资料群"、考试周疯传的笔记。证明课程维度知识共享有真实需求，但当前以非结构化、不可检索、时效性差的方式存在。智阶可以将这些散落的材料结构化+叠加AI处理。

**留学生群体的特殊机会**：在TUM学离散数学的中国学生，可以参考清华中文版知识解析辅助理解德语授课内容。全球100万+中国留学生面临语言+课程理解的双重挑战。建议在TUM、ETH、Delft等中国留学生密集的欧洲理工院校进行早期推广——这个群体的口碑传播和付费意愿都高于国内大学生。

### 2.4 冷启动三阶段策略

Researcher-D系统评估了三种冷启动方案后，推荐三阶段递进组合：

**版权风险评估**：

| 来源 | 许可证 | 风险等级 |
|------|--------|---------|
| MIT OCW | CC BY-NC-SA | 🟢 低（非商业可用） |
| OpenStax | CC BY | 🟢 极低（完全开放） |
| NPTEL | CC BY-SA | 🟡 中低（需保持开放） |
| 中国大学MOOC | 版权保留 | 🔴 高（禁止） |
| 各高校官网课件 | 不明确 | 🔴 高（需逐一确认） |

**三阶段方案**：

**Phase 0（立即）：OER种子 + 手动精选**
- 爬取 MIT OCW / OpenStax / Khan Academy 的课程大纲和结构
- LLM自动解析课程结构→生成知识网络骨架
- 手动精选 20-30 门热门课程的高质量材料
- 产出：知识网络有骨架，热门课程有种子材料

**Phase 1（1-2月）：用户上传 + AI归并**
- 上传即获得AI分析→用户的核心上传动力（即使只有一个用户也有价值）
- AI自动将新材料映射到已有知识网络节点
- 社区贡献度可见（"本课程已有X份材料，Y人在学"）
- 产出：用户贡献填充长尾内容

**Phase 2（3-6月）：机构合作 + 内容结构化**
- 用Phase 0-1的数据和用户量作为谈判筹码
- 与试点高校合作获取授权内容
- 产出：高质量授权内容+品牌背书

**关键洞察**：智阶的冷启动优势在于**AI工具本身就是上传动力**。用户上传不是为了"分享给社区"，而是为了"让AI帮我分析课件"。即使只有一个用户也有独立价值——这比Quizlet式的纯UGC冷启动更可行。

### 2.5 跨学校材料组织架构

Researcher-D设计了三层组织架构解决"同名课程内容差异"的问题：

```
知识网络节点（通用）
  └── 线性代数
       ├── [通用知识点层]
       │    ├── 向量空间
       │    ├── 线性变换
       │    ├── 特征值与特征向量
       │    └── ...
       │
       ├── [学校变体层]
       │    ├── TUM - Lineare Algebra I (WS2025)
       │    │    ├── 材料A: Vorlesung-Skript.pdf
       │    │    └── 材料B: Übungsblätter.pdf
       │    ├── ETH - Linear Algebra (HS2025)
       │    │    └── 材料C: Lecture-Notes.pdf
       │    └── 清华 - 线性代数 (2025秋)
       │         └── 材料D: 教材配套课件.pdf
       │
       └── [AI 归并映射]
            材料A:第3章 ←→ 通用:特征值 ←→ 材料D:第5章
```

**AI归并算法**：(1) Cartographer概念提取 → (2) LLM跨语言语义对齐（置信度>0.85=相同概念）→ (3) 投票生成通用先修关系DAG → (4) 差异标注（各校独有内容）。

**用户视图**：默认"通用知识点视图"；设置"我的学校"后优先展示本校材料；支持跨校对比（"TUM用几何方法讲解，清华用代数方法讲解"）。

### 2.6 知识网络与学习工作台深度集成

Researcher-D设计了完整的数据流架构，知识网络作为核心数据结构驱动推荐、追踪、规划：

```
知识网络（核心）
  [课程节点] → [知识点节点] → [材料节点]
       │             │              │
       ↓             ↓              ↓
  先修关系图    BKT mastery    AI分析产出
                  per-node
                     │
        ┌────────────┼────────────┐
        ↓            ↓            ↓
   学习工作台    闪卡系统     统一日程
        │            │            │
        └─────┬──────┘            │
              ↓                   ↓
    BKT mastery 更新 ←── 测验/复习结果
              │
              ↓
    知识网络节点颜色/进度更新
```

**掌握度自动更新**：测验完成→BKT更新；闪卡复习→mastery微调（Again/Hard微降，Good/Easy维持/微升）；阅读行为→隐式信号（停留时间推断难度）。

**"下一个该学什么"推荐算法**：找到先修条件已满足（mastery>70%）且自身未掌握（mastery<85%）的节点，按学习意图排序——考前模式按exam_weight×(1-mastery)，学透模式按拓扑序，复习模式按mastery衰减最大优先。

**mastery可视化**：知识图谱中节点颜色从灰色(0%)→浅红(30%)→暖黄(70%)→深绿(100%)，完成学习后颜色渐变动画。

### 2.7 防止"变成网盘"的五原则

Researcher-D指出：类似平台（百度文库、CourseHero）沦为网盘的根本原因是"上传和下载是终点，不是起点"。

**原则1：打开即学习，不是打开即下载**
- 点击材料进入学习工作台，不是看到"下载"按钮
- 第一触点是AI分析结果（模块拆解、考点地图），不是原始PDF
- **不提供"仅下载"功能**——要获取材料，必须进入工作台

**原则2：AI工具是必经之路，不是可选附件**
- 上传后AI自动运行分析，不需要手动触发
- 材料详情页主信息是"5个模块·已分析·推荐从模块2开始"，不是文件名和大小

**原则3：学习行为可见，存储行为不可见**
- 社区看到的是"XX正在学习线性代数模块3"，不是"XX上传了课件"
- 材料价值度量是"被多少人深度学习过"，不是"被下载了多少次"

**原则4：知识网络是学习地图，不是文件夹结构**
- 课程节点显示"模块掌握度热力图"，不是文件列表
- 导航逻辑是"我接下来该学什么"（AI推荐），不是"我要找哪个文件"

**原则5：强制FSRS闭环**
- 学完模块后自动生成闪卡加入复习队列——不让学过的知识石沉大海
- 系统通过日程提醒复习到期闪卡
- 这是NotebookLM/CourseHero等工具型产品完全缺失的

**关键成功指标**：上传后24h内进入工作台学习比例>60%；打开材料后平均学习时长>15分钟（vs 网盘式平台<2分钟）。
