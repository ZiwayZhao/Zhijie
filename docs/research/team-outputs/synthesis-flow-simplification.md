# 交叉分析：动线简化核心方案
> 作者：synthesis-analyst | 2026-03-18

## 来自各 Topic 的关键发现（交叉阅读总结）

### Topic 1 → Topic 2 的关联

Topic 1 识别出 **17 步 / 8 决策点** 的流程，其中三大摩擦点为：
1. 2-5 分钟管道等待（致命级）
2. 意图选择 + 背景信息采集的认知门槛（高摩擦）
3. 模块间无连续学习流（中高摩擦）

Topic 2 对这些摩擦点做了场景化解释，**核心发现是三条路径共享同一管道是根本问题**：
- `startDisassembly()` 不接受 intent 参数，gathering 收集的数据被完全丢弃（`_data` 前缀）
- Intent `review` 被映射为 `'learn'` → 三种场景**执行完全相同的后端逻辑**
- **复习场景根本不应进入 disassembly 管道**——这是一条假流程

**关联结论**：Topic 1 的"工具箱心态 vs 体验心态"诊断被 Topic 2 的代码级证据完全证实——不是 UI 问题，而是**架构未按场景分叉**的问题。

### Topic 1+2 → Topic 3 的关联

Topic 3 将 Topic 1 的诊断和 Topic 2 的场景分析转化为**具体的前端分叉方案**：
- **核心策略确认**：三条路径必须在前端分叉，每条只走最短流程
- **Gathering 表单三条路径均可省略**：数据要么被丢弃（exam/learn 的 familiarity），要么不需要（review）；mastery 由 BKT 自动推断
- **复习路径降至 1 步**（比 Topic 2 的 2 步更激进）：直接进闪卡，无需选材料
- **"AI 先行，用户确认"原则**：AI 可自动化低风险决策（排序、起始模块、复习顺序），但意图选择和学习计划确认必须留给用户
- **与 OpenMAIC 的差异定位明确**：在接近 OpenMAIC 简洁度（2-3步）下，保持远超其个性化深度（BKT mastery + 模块级粒度）

**关键实施洞察**：Topic 3 的 P0 改动全部是"删代码"性质——省略 gathering、条件跳过 plan-preview、review 绕过管道——实施风险极低。

### Topic 2 → Topic 5 的关联

Topic 2 明确了三种场景的最短路径（考前冲刺 2 步、深度学习 3 步、日常复习 2 步），Topic 5 则为这些路径中的关键触点提供了体验细节方案：

| Topic 2 的场景痛点 | Topic 5 的对应方案 |
|---|---|
| 考前冲刺用户无法忍受 2-5min 等待 | 等待阶段加预估倒计时 + 阶段完成总结 + 后台处理模式 |
| 模块间手动导航打断学习流 | 内容底部"下一模块"引导 + 键盘快捷键 + 阅读进度自动标记 |
| 完成模块无反馈导致放弃 | 进度可视化 + 克制的正反馈（checkmark draw、数字递增） |
| Quiz 答错无行动引导 | 跳转精讲 + 一键加入闪卡 + 薄弱模块分析 |

**关联结论**：Topic 5 的"Never Leave a Dead End"原则直接回应了 Topic 2 中各场景的流失节点——**每个步骤结束时必须有明确的下一步**。

### 审计报告的补充发现

审计报告（2026-03-17）确认了技术层面的关键事实：
- 8 个手动工具**全部是占位符**（无后端 API）
- Socratic 对话是**模板制**，非 LLM 驱动
- FSRS 已集成但**未充分使用**（闪卡生成入口未实现）
- BKT 学生模型**仅用于对话脚手架**，未驱动路径调整

### 竞品印证的核心结论

三款竞品的动线步骤对比验证了我们的诊断：

| 产品 | 到达首个有用输出 | 用户决策点 | 核心模式 |
|------|----------------|-----------|---------|
| **OpenMAIC** | 2 步（上传→进入课堂） | 0（零配置） | AI 全自动课堂 |
| **NotebookLM** | 2-3 步（上传→自动洞察） | 0（上传即开始） | 一键生成高价值产出 |
| **Khanmigo** | 2-3 步（打开内容→AI自动开始） | 0-1 | 上下文感知辅导 |
| **智阶当前** | 8-17 步 | 5-8 | 工具箱手动拼装 |

**三款竞品的共同模式**（全部印证了 Topic 1 的"体验心态 vs 工具箱心态"诊断）：
1. **零配置启动**：都不要求用户选择"学习模式"或填写背景信息
2. **AI 主动推断意图**：Khanmigo 从用户当前行为推断，NotebookLM 从文档内容推断，OpenMAIC 不需要推断（统一课堂）
3. **即时价值呈现**：NotebookLM 上传后秒出 Notebook Guide，Khanmigo 点击即对话，OpenMAIC 虽需 30min 但等待与使用完全解耦

**智阶的差异化优势（竞品都缺失的）**：
- **深度教学流水线**（3-Agent 串行管道）— 竞品只做摘要/对话，不做逐页精讲+结构化测验
- **FSRS 闪卡系统** — NotebookLM 2025 才加基础闪卡，无 FSRS 调度；Khanmigo/OpenMAIC 无闪卡
- **BKT + HTN 个性化路径** — 竞品都是固定流程，无动态路径调整
- **多模式意图适配** — 竞品都是单一模式

**竞品研究一句话总结**：智阶的问题不是功能不够，而是**动线太长把强大功能埋没了**。需要把 17 步压缩到 3 步，让后端能力以"一键体验"形式呈现。

**可直接移植的竞品模式**：
| 来源 | 模式 | 智阶移植方案 | 对应 Phase |
|------|------|------------|-----------|
| NotebookLM | 上传后自动生成"材料导览" | Cartographer 完成后自动展示模块概览 + 建议起点 | Phase 0-1 |
| Khanmigo | AI 根据上下文主动推荐下一步 | 精读完自动弹出"做个测验？"；答错自动触发 Socratic | Phase 1 |
| NotebookLM | 一键生成按钮（FAQ/Study Guide/Timeline） | 工具从"先选模式再配置"→"一键生成" | Phase 1 |
| OpenMAIC | 第一个模块完成即可开始学习 | SSE 推送 `module_specialist_ready`，先出先看 | Phase 1 |
| Khanmigo | 苏格拉底式"永远不给答案" | Socratic 从模板制升级为 LLM 驱动 | Phase 2 |

### 三场景最终路径

**考前冲刺**（目标：≤2 步）
```
① 上传/选择材料 + 填考试日期
  ↓ [AI 自动：备考模式，跳过 gathering，管道启动]
  ↓ [等待期间：预估时间 + 阶段总结 + "你知道吗"彩蛋]
② 直接看到：考点清单（按权重排序）+ 薄弱项标注 + 一键进入模拟测验
  ↓ [AI 编排：答错→跳转精讲→加入闪卡；答对→下一考点]
```

**深度学习**（目标：≤3 步）
```
① 上传/选择材料（无考试日期 → 自动识别为深度学习）
  ↓ [管道启动，第 1 个模块完成即推送]
② 确认/微调学习计划（plan-preview 保留，仅此场景）
③ 自动进入第 1 个模块精读 → AI 驱动连续流
  ↓ [精读完 → "做个测验？" → 答错 → Socratic 引导 → 下一模块]
  ↓ [模块底部自动追加"下一模块"引导]
```

**日常复习**（目标：1 步，Topic 3 验证可行）
```
① 从首页/闪卡入口选"快速复习" → 直接进入 FSRS 闪卡会话
  ↓ [有到期闪卡 → 直接翻卡；无闪卡但有分析结果 → 自动生成后翻卡]
  ↓ [连续忘记 3 次 → AI 自动拆分为子卡]
  ↓ [全部复习完 → "今日复习完成" + 进度统计]
```
> Topic 3 关键洞察：复习完全不依赖 disassembly 管道，纯前端实现（FSRS + localStorage），无需后端配合。

### AI 应该替用户做的决策清单

| # | 当前需用户决策 | AI 替代方案 | 实现方式 |
|---|--------------|------------|---------|
| 1 | 选择意图（学透/备考/复习） | **根据有无考试日期自动判断**；复习从独立入口进 | 前端逻辑：有 examDate → exam，无 → learn；闪卡入口 → review |
| 2 | 填写熟悉度（zero/basic/advanced） | **首次默认 basic，后续由 BKT mastery 驱动** | 删除 familiarity 表单，BKT 初始值 pL0=0.3 即"basic" |
| 3 | 确认学习计划 | **考前/复习场景跳过确认**；深度学习保留但默认推荐 | 前端状态机按 intent 分叉 |
| 4 | 选择从哪个模块开始 | **AI 按拓扑序/权重/mastery 自动推荐** | `generatePlanSteps()` 输出的第一个 step 自动加载 |
| 5 | 决定何时做测验 | **精读完自动弹出"巩固测验？"** | 模块底部 CTA + AI 编排逻辑 |
| 6 | 决定是否进入 Socratic 对话 | **答错后自动触发 Socratic** | Quiz 答错 → Socratic 对话引导 → 回到下一题 |
| 7 | 选择下一个模块 | **自动推进到推荐的下一模块** | "下一模块"按钮 + 键盘快捷键（← →） |
| 8 | 决定何时生成闪卡 | **答错题自动转闪卡 + 模块完成后批量生成** | QuizPanel 答错 → 一键加入闪卡；CompletePhase → 批量生成 |

## 分阶段实施路线图

### Phase 0：快速胜利（1 周内，纯前端，Topic 3 的 P0 清单）

**目标**：在不改后端的前提下，将体验从 17 步大幅缩短。**核心思路是"删代码"——省略不必要的步骤。**

| # | 改动 | 具体实现 | 文件 | 工作量 |
|---|------|---------|------|--------|
| 1 | **三条路径省略 gathering 表单** | `handleIntentSelect()` 中 learn/exam 直接调用 `startProcessing`，不进入 gathering 相位 | `AIToolPanel.tsx` | 0.5d |
| 2 | **复习路径绕过 disassembly 管道** | `handleIntentSelect('review')` 检查 localStorage 闪卡，有→直接进 ReviewSession，无但有分析结果→自动生成闪卡 | `AIToolPanel.tsx`, 路由 | 1d |
| 3 | **考前冲刺跳过 plan-preview** | 管道完成后 exam intent 直接跳到 complete（条件跳过一个相位） | `AIToolPanel.tsx` 状态机 | 0.5d |
| 4 | **模块底部追加"下一模块"引导块** | Markdown 渲染区底部追加分隔线 + 下一模块名 + [继续学习→] + [做测验✎] | `MaterialReader.tsx` | 1d |
| 5 | **CompletePhase 自动加载第一个模块** | 优化 `autoSelectFirstModule` 逻辑，所有 intent 都自动打开推荐模块 | `AIToolPanel.tsx` | 0.5d |
| 6 | **ProcessingView 加预估时间 + 阶段总结** | 节点完成时显示"已提取 47 页""识别出 6 个模块"等有信息量的总结（Topic 5 方案） | `ProcessingView.tsx` | 1d |
| 7 | **Quiz 答错后加行动引导** | 错误解析区底部增加"📖 查看精讲 §3.2"+"🃏 加入闪卡"链接 | `QuizPanel.tsx` | 1d |
| 8 | **模块完成标记 + 进度条** | 已查看模块添加 ✓ 标记，顶部显示 `3/6 模块已学习` 进度条 | `CompletePhase` 组件 | 0.5d |

**预期效果**（与 Topic 3 步骤对比一致）：
- 考前冲刺：5 步 → 2 步（-60%）
- 深度学习：6 步 → 3 步（-50%）
- 日常复习：5+ 步 → 1 步（-80%），完全绕过工作台

### Phase 1：场景分叉（1 个月，前端重构 + 少量后端）

**目标**：实现三场景差异化路径，步骤降到 ≤5 步

| 改动 | 涉及范围 | 工作量 |
|------|---------|--------|
| **意图智能推断**：删除三选一 UI，根据上下文自动判断 | 前端：`IdlePhase` 重设计 + `GatheringPhase` 精简为 1 字段 | 3d |
| **状态机按场景分叉**：exam 跳过 gathering+plan-preview，review 跳过全部 | `AIToolPanel.tsx` 状态机重构 | 3d |
| **后端 intent 传参生效**：`startDisassembly` 接受 intent，Specialist 按 intent 调整输出详细度 | 后端 `disassembly.py` | 3d |
| **流式模块推送**：Specialist 完成 1 个模块即推送前端 | 后端 SSE + 前端订阅逻辑 | 5d |
| **AI 驱动连续学习流**：精读完 → 自动推荐测验 → 答错 → Socratic → 下一模块 | 新增 `LearningOrchestrator` 组件 | 5d |
| **闪卡生成实际接通**：Quiz 答错一键转闪卡 + 模块完成批量生成 | `QuizPanel.tsx` + `fsrs.ts` | 3d |

**预期效果**：
- 考前冲刺：2-3 步
- 深度学习：3-4 步
- 日常复习：2 步（从首页直达闪卡）

### Phase 2：智能编排（季度级，后端 + AI 改造）

**目标**：实现 CLAUDE.md 描述的"5 层混合 AI 教师"架构

| 改动 | 涉及范围 | 工作量 |
|------|---------|--------|
| **学习编排引擎**（LearningOrchestrator 升级）：中央状态机协调所有工具 | 前端架构重构 | 2w |
| **动态路径调整**：Quiz 结果 → BKT 更新 → 自动重新规划 | 前端 + 后端 | 2w |
| **Socratic 对话 LLM 化**：模板制 → 真正的 LLM 驱动 | 后端新 API | 2w |
| **高级工具后端实现**：考点提取、易错总结、概念图谱 | 后端 3 个新 Agent | 3w |
| **闪卡自进化**：连续忘记→拆分，连续简单→退役 | 前端 + LLM API | 1w |
| **HTN 学习路径规划器**：真正的个性化计划生成 | 后端新模块 | 2w |

**预期效果**：
- 所有场景：≤3 步到达核心价值
- 学习路径真正个性化（不同学生看到不同模块顺序和工具组合）
- 课堂结业率目标：>30%（对标 OpenMAIC 40%）
