# Topic 2：用户场景拆分与最短路径
> 作者：product-strategist | 2026-03-18

## 场景A：考前冲刺

**理想路径**（步骤数 ≤ 3）：
1. 选"备考冲刺" → 2. 看到高频考点+薄弱项 → 3. 做题验证

**当前路径中多余的步骤**：
- `startDisassembly()` API **不接受 intent 参数**（body 只有 `material_id`），gathering 收集的 `examDate`/`masteryLevel` 被完全丢弃（`_data` 下划线前缀）
- intent `review` 被映射为 `'learn'` 发给后端——三种场景**实际执行完全相同的管道**
- Plan Preview 对考前冲刺是多余环节：焦虑的考前学生不想看"5步学习计划"

**最短可接受路径**：
选"备考冲刺" → 自动跳过gathering（或只问考试日期1个字段） → 直接出考点清单+薄弱项标注 → 一键进入测验

**关键差异化需求**：
- 需要时间压力感知（倒计时天数）
- 输出以"考点清单"为主而非"学习计划步骤"
- 后端应差异化：exam intent 让 Specialist 精简输出，Examiner 增加题量

## 场景B：深度学习

**理想路径**（步骤数 ≤ 3）：
1. 选"学透这份材料" → 2. 确认/微调学习计划 → 3. 逐模块精读+交互问答

**当前路径中多余的步骤**：
- `familiarity`（zero/basic/advanced）在 `generatePlanSteps()` 和 API 调用中均未使用
- 计划步骤是"精读"+"最后一步测验"的固定模板，不因 familiarity 调整

**最短可接受路径**：
选"学透" → 跳过 gathering（familiarity 可隐式判断）→ 展示学习计划（plan-preview 有价值保留）→ 进入精读+苏格拉底对话

**关键差异化需求**：
- 唯一需要 plan-preview 的场景（深度学习是持续多日投入，值得确认计划）
- 需要模块间进度持久化（当前缺失）
- 苏格拉底对话目前是模板制非LLM驱动，是最大体验缺口

---

## 场景C：日常复习

**理想路径**（步骤数 ≤ 3）：
1. 选"快速复习" → 2. 直接看今日到期闪卡 → 3. 翻卡评分

**当前路径中多余的步骤**：
- **整个 disassembly 管道是不必要的**：复习不需要重新分析 PDF
- 当前 review 走完整 2-5 分钟分析管道，生成全部 action='flashcard' 的 plan，但没有实际的闪卡数据——是**假流程**
- Plan Preview 对复习场景是噪音：用户期望像 Anki 一样"打开就复习"

**最短可接受路径**：
选"快速复习" → 直接显示今日到期闪卡数量 → 进入闪卡复习会话（不走 disassembly 管道）

**关键差异化需求**：
- 完全不依赖 disassembly 管道，依赖 FSRS 闪卡系统
- 需要"无材料上下文也能复习"的入口
- 回答时间应被记录用于自进化触发

---

## 跨场景对比

| 维度 | 考前冲刺 | 深度学习 | 日常复习 |
|------|---------|---------|---------|
| 理想步骤数 | 2 | 3 | 2 |
| 最需要的单一功能 | 考点清单+薄弱标注 | 模块精读+苏格拉底问答 | FSRS 闪卡复习 |
| 最不需要的步骤 | Gathering + Plan Preview | Gathering familiarity | 整个 disassembly 管道 |
| 容忍等待时间 | ≤30s（焦虑状态） | 2-5min（可接受） | 0s（即开即用） |
| 当前实际步骤数 | 5 | 5 | 4 |
| 步骤膨胀率 | 2.5x | 1.67x | 2x |

## 关键洞察

1. **三条路径共享同一管道是核心问题**：`startDisassembly` 不接受 intent，gathering 数据被丢弃，三种场景执行完全相同的后端逻辑——**零差异化**。

2. **Review 场景根本不应进入 disassembly 管道**：复习的本质是间隔重复，数据来源应是 FSRS 闪卡库而非重新分析 PDF。当前是假流程。

3. **Gathering → Plan Preview 两步确认对 exam/review 是过度设计**：只有 learn（深度学习）场景的用户心态支持多步确认。当前统一的 5 步状态机应按场景分叉。
