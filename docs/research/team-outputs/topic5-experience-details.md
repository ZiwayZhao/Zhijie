# Topic 5：体验细节打磨
> 作者：experience-designer | 2026-03-18

## 触点1：长时等待（后端处理2-5分钟）

**问题诊断**：ProcessingView 4节点时间线信息密度低，2-5分钟内几乎没有内容变化，用户无法判断"还要等多久"。

**改善方案**：
1. **预估时间 + 倒计时**：每个阶段显示预估剩余时间（"约 45 秒"）。文案示例：`解析文档 · 约 30 秒` → `分析结构 · 约 1 分钟`
2. **阶段完成总结文案**：节点完成时显示有信息量的总结而非仅打勾：
   - 解析文档 ✓ → `已提取 47 页内容`
   - 分析结构 ✓ → `识别出 6 个知识模块`
   - 生成精讲 ✓ → `生成 12,400 字精讲笔记`
   - 生成测验 ✓ → `生成 10 道测验题`
3. **"你知道吗"学习彩蛋**：等待超过 30 秒后轮播学科相关趣味知识，风格参考 Linear 简洁文案
4. **允许后台处理**：增加"最小化"按钮，分析完成后以 toast 通知

**微交互**：阶段完成时节点 ✓ 有 scale(0.8→1.0) 轻微弹入（120ms）；预估时间用 `tabular-nums` 等宽数字；"你知道吗"文案 crossfade 切换每 8 秒

## 触点2：错误/异常处理

**问题诊断**：ErrorPhase 极其简陋，重试 = 完全重新开始，用户丢失已等待进度。无错误分类，无降级策略。

**改善方案**：
1. **错误分类 + 差异化处理**：
   - 网络错误：自动重试 2 次，无需用户干预
   - 单模块失败：跳过继续，标记"1个模块失败，可单独重试"
   - 管道崩溃：显示错误+重新分析，但保留PDF批注等用户侧数据
2. **部分降级可用**：Specialist完成但Examiner失败，仍进入complete展示精讲，Quiz区域显示"测验生成失败·重试"
3. **错误文案人性化**：用"分析引擎暂时繁忙"替代技术错误码
4. **保留已完成阶段**：时间线上已完成节点保持 ✓，只有失败节点显示 ✗ + 局部重试按钮

**微交互**：错误节点轻微 shake（±3px，2次，300ms）；自动重试显示 ↻ + "正在重试(1/2)"；降级功能用 50% opacity + 虚线边框

## 触点3：学习完成后的成就感

**问题诊断**：当前完成模块后无任何正反馈，CompletePhase 是静态列表，ScoreSummary 是冷冰冰数字。

**改善方案**：
1. **模块完成标记 + 进度可视化**：已查看模块添加 `✓ 已学习`（accent-gold色）；模块列表顶部显示 `3/6 模块已学习` 进度条；全部完成变为 `🎓 全部完成`
2. **测验高分庆祝**：80%+ 时标题变为"出色的表现"，分数有从0递增的计数动画；100%全对时出现细长confetti条纹（red-primary + accent-gold，1秒后消失）
3. **学习连续性激励**：首页"今日已学习 X 分钟"计时器；完成当日任务后首页卡片显示 `今日任务已完成` + accent-gold 边框
4. **模块间里程碑**：连续完成3个模块时短暂显示鼓励文案（fade-in → 5秒后fade-out）

**微交互**：模块完成 ✓ 有 checkmark draw 动画（stroke-dashoffset）；分数计数用 ease-out 600ms；全对 confetti 20个小圆点上飘消失，总时长 1.2 秒，不循环

## 触点4：模块间过渡体验

**问题诊断**：用户不知道何时"读完"，需视线从左侧跳到右侧面板再跳回来，流程断裂。

**改善方案**：
1. **内容底部"下一模块"引导**：精讲 Markdown 最底部追加区块：
   ```
   ─────────── 模块 3/6 完成 ───────────
   下一模块：§4 应力-应变关系
   [继续学习 →]    [做测验 ✎]
   ```
2. **右侧面板当前模块高亮**：当前阅读模块用 `bg-bg-accent` + `border-l-accent-gold` 高亮
3. **键盘快捷键**：`←` `→` 切换模块，首次使用时 tooltip 提示
4. **阅读进度追踪**：滚动到底部 80% 时，右侧面板自动标记当前模块为"已读"（IntersectionObserver）

**微交互**："下一模块"区块进入视口时 fade-in（y 8→0）；模块切换时 MaterialReader 内容区 crossfade（旧内容 150ms fade-out → 新内容 200ms fade-in）

## 触点5：Quiz 答错即时反馈

**问题诊断**：答错后无"为什么此选项错"的对比分析；答错后没有行动引导（跳转精讲、加入闪卡）；ScoreSummary 的"需加强"没有具体指出薄弱模块。

**改善方案**：
1. **答错后行动引导**：错误解析区块底部增加：
   - `📖 查看精讲 §3.2` — 跳转对应模块精讲
   - `🃏 加入闪卡` — 将错题转为 Basic Q&A 类型 FlashcardNote
   按钮用 text link 风格，不做重按钮
2. **选项对比分析**：答错时额外说明用户所选选项为何不正确（近期前端规则，远期后端 `option_explanations` 字段）
3. **ScoreSummary 薄弱点分析**：全部答完后显示薄弱模块区块（按错误率排序 + 跳转链接）
4. **答题实时统计条**：在顶部显示 `5/8 已作答 · 正确率 60%`，低于 50% 时文字变为 `text-red-primary`

**微交互**：答错时错误选项 border shake（±2px，2次，200ms）；行动引导按钮延迟 500ms fade-in；薄弱模块用 stagger 动画（delay: index * 0.08s）

## 体验原则总结

1. **永远提供下一步（Never Leave a Dead End）**：任何状态终点都必须给出明确的下一步行动选项。
2. **进度感知驱动信心（Progress Fuels Confidence）**：将等待预估时间、模块完成比例、测验正确率等进度对用户可见。
3. **克制的正反馈（Restrained Celebration）**：用精准文案、颜色变化（accent-gold）、微妙动画（checkmark draw、数字递增）替代夸张弹窗。学术产品的庆祝应像论文被接收时的一句"Congratulations"。
