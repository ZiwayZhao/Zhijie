### 增量同步 API
- 推荐基于 `cursor`，不要只靠裸时间戳
- 理由：
  - 时间戳有时钟漂移、精度和重复问题
  - 自增 `sync_events.id` 更稳定
- API：
  - `POST /api/v1/sync/push`
    - 上传本地变更集
  - `GET /api/v1/sync/pull?cursor=12345&limit=500`
    - 拉服务器增量
  - `POST /api/v1/sync/ack`
    - 客户端确认消费到某 cursor
- push payload 示例
```json
{
  "client_id": "web-abc",
  "base_cursor": 12300,
  "changes": [
    {
      "entity_type": "flashcard_card",
      "entity_id": "uuid",
      "op": "upsert",
      "updated_at": "2026-03-16T10:00:00Z",
      "data": { "fsrs_state": {} }
    }
  ]
}
```

### 同步策略
- 本地写入先落 IndexedDB
- 后台队列批量 push
- pull 到的数据按实体类型写回 IndexedDB
- UI 永远从本地缓存读，保证秒开和离线可用

### WebSocket vs 轮询
- 推荐：
  - `WebSocket` 用于登录后的轻实时通知
  - `轮询/前台 pull` 做兜底同步
- 理由：
  - WebSocket 对多端同时在线的学习进度、笔记更新提醒更好
  - 但断线、移动网络切换常见，不能只依赖 WS
- 实践：
  - 连接建立后只推“有变更”事件，不直接传全量数据
  - 收到事件后调用 `/sync/pull`

### 离线支持
- `Service Worker`
  - 缓存静态资源、最近访问课程页、PDF 元信息
- `IndexedDB`
  - 存 flashcards、notes、progress、upload queue、sync queue
- 断网时：
  - 继续做闪卡复习、看已缓存材料、记笔记
  - 待恢复网络后自动 push/pull

### React 组件 spec
- `SyncProvider`
  - 管 cursor、网络状态、后台同步
- `useSyncStatus`
  - 暴露 `isSyncing/lastSynced/conflicts`
- `OfflineBanner`
  - 显示离线状态与待同步数量
- `ConflictResolutionModal`
  - 仅在笔记冲突或大对象覆盖时弹出
- `useIndexedEntityStore`
  - 按实体类型统一缓存接口

## 1. 知识网络系统

### 技术选型
- 社区模型：采用 `课程节点 -> 学校节点 -> 班级/学期节点 -> 材料帖子` 四层。
- 搜索选型：主推 `Meilisearch`。
- 理由：
  - `PostgreSQL tsvector` 适合早期低成本启动，和主库一致性最好，但排序、拼写容错、前缀匹配、中文体验一般。
  - `Typesense` 也适合搜索产品，但生态和中文分词集成通常不如 Meilisearch 顺手。
  - `Meilisearch` 在“课程名、学校名、帖子标题、标签、教师名、教材名”的容错搜索、前缀补全、权重排序上更实用，接入成本低。
- 建议：
  - MVP：`PostgreSQL tsvector + trigram`
  - 正式版：`Meilisearch` 主搜索，PostgreSQL 兜底过滤与权限校验

## 2. 文件上传 + 云存储

你当前上传交互已经有基础组件，例如 [src/components/upload/DropZone.tsx](/Users/ziway/Downloads/工程项目/智阶新版/src/components/upload/DropZone.tsx)。但材料仍应从 `localStorage/base64` 迁到对象存储。

### 存储选型
- `AWS S3`
  - 优点：成熟、生态最全、SDK/权限/CDN/生命周期齐全
  - 缺点：出网费用高，国内访问未必最优
- `Cloudflare R2`
  - 优点：对外分发成本低，和 CDN 结合好，适合文档下载/预览
  - 缺点：S3 兼容但少数高级能力不完全一致
- `MinIO`
  - 优点：自建、可私有化、开发测试方便
  - 缺点：生产运维成本高
- 建议：
  - 开发/测试：MinIO
  - 正式版：R2 优先；若企业客户或生态要求高，用 S3

### 直传 vs 后端中转
- 直传 `presigned URL`：推荐默认方案
  - 优点：后端带宽压力小、上传更快、适合大文件、可直接走 CDN 边缘
  - 缺点：前端流程更复杂，需要先申请上传会话
- 后端中转：
  - 优点：统一鉴权、统一病毒扫描/转码入口
  - 缺点：服务器带宽和 CPU 压力大
- 建议：
  - 普通文档走直传
  - 需要同步做安全扫描或格式转换的少数文件，上传后异步处理，不做中转阻塞

### 文件链路
1. 前端请求创建上传会话
2. 后端返回 `file_id + presigned_put_url + object_key`
3. 前端直接 PUT 到对象存储
4. 前端回调 `complete` 接口
5. 后端写入 `files` / `material_files`
6. 异步任务抽取文本、生成缩略图、PDF 首屏图、写搜索索引

## 3. 用户认证系统

### 认证方案
- Access Token：JWT，15 分钟
- Refresh Token：随机串或 JWT 均可，但我建议“数据库持久化 refresh token + JWT access token”
- 理由：
  - access token 无状态，适合 API
  - refresh token 可撤销、可做设备维度管理
- 第三方登录：
  - Google OAuth2：标准 OIDC
  - 微信登录：Web 端建议扫码登录，需区分开放平台/AppID 场景

### 安全最佳实践
- 密码哈希只存 `bcrypt/argon2`

- 邮箱验证、异常设备提醒、会话管理页
- JWT 携带 `sub/session_id/token_version`

- 闪卡：卡片、note、FSRS 调度状态、review logs
- 学习进度：课程完成度、模块状态、最近访问
- 笔记：正文、标签、锚点、PDF 高亮
- 日程：待办、考试日期、提醒设置

### 冲突策略
- `Last-Write-Wins`：推荐用于
  - 学习进度
  - 设置项
  - 日程状态
- `CRDT`：仅推荐用于
  - 富文本笔记协作
  - 多端同时编辑的长文本
- 结论：
  - 你的场景初版不要全量上 CRDT，复杂度过高
  - 先做“对象级 LWW + 操作日志补偿”
  - 笔记若后续支持多人协作，再单独引入 Yjs/Automerge

### 增量同步 API
- 推荐基于 `cursor`，不要只靠裸时间戳
- 理由：
  - 时间戳有时钟漂移、精度和重复问题
  - 自增 `sync_events.id` 更稳定
- API：
  - `POST /api/v1/sync/push`
    - 上传本地变更集
  - `GET /api/v1/sync/pull?cursor=12345&limit=500`
    - 拉服务器增量
  - `POST /api/v1/sync/ack`
    - 客户端确认消费到某 cursor
- push payload 示例
```json
{
  "client_id": "web-abc",
  "base_cursor": 12300,
  "changes": [
    {
      "entity_type": "flashcard_card",
      "entity_id": "uuid",
      "op": "upsert",
      "updated_at": "2026-03-16T10:00:00Z",
      "data": { "fsrs_state": {} }
    }
  ]
}
```

### 同步策略
- 本地写入先落 IndexedDB
- 后台队列批量 push
- pull 到的数据按实体类型写回 IndexedDB
- UI 永远从本地缓存读，保证秒开和离线可用

### WebSocket vs 轮询
- 推荐：
  - `WebSocket` 用于登录后的轻实时通知
  - `轮询/前台 pull` 做兜底同步
- 理由：
  - WebSocket 对多端同时在线的学习进度、笔记更新提醒更好
  - 但断线、移动网络切换常见，不能只依赖 WS
- 实践：
  - 连接建立后只推“有变更”事件，不直接传全量数据
  - 收到事件后调用 `/sync/pull`

### 离线支持
- `Service Worker`
  - 缓存静态资源、最近访问课程页、PDF 元信息
- `IndexedDB`
  - 存 flashcards、notes、progress、upload queue、sync queue
- 断网时：
  - 继续做闪卡复习、看已缓存材料、记笔记
  - 待恢复网络后自动 push/pull

### React 组件 spec
- `SyncProvider`
  - 管 cursor、网络状态、后台同步
- `useSyncStatus`
  - 暴露 `isSyncing/lastSynced/conflicts`
- `OfflineBanner`
  - 显示离线状态与待同步数量
- `ConflictResolutionModal`
  - 仅在笔记冲突或大对象覆盖时弹出
- `useIndexedEntityStore`
  - 按实体类型统一缓存接口

## 实施顺序

1. 先上认证系统和用户表，否则后续所有云端能力没有主体。
2. 再做对象存储上传，把材料从 `localStorage` 迁出。
3. 接着做同步层，把 FSRS、Agenda、Notes 改成 IndexedDB + 云端副本。
4. 最后做知识网络与搜索，因为它依赖用户、材料、课程元数据逐渐积累。
