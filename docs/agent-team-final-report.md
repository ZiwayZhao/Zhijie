## 执行摘要

智阶当前从"打开材料"到"开始学习"需要 **17 步、8 个用户决策点、5-8 分钟**。对比竞品 OpenMAIC（3步/0决策点）、Khanmigo（3步/0决策点）、NotebookLM（2步/0决策点），差距极为显著。

**根本问题不在 UI，而在架构**：三种学习场景（考前冲刺/深度学习/日常复习）共享同一管道，但 `startDisassembly` API 不接受 intent 参数，gathering 收集的数据被完全丢弃，review 被映射为 learn——三条路径执行的是**完全相同的后端逻辑（零差异化）**。

**核心改进方向**：三路径分叉 + AI 替代前置决策，将步骤压缩到：
- 考前冲刺：**2 步**（-60%）
- 深度学习：**3 步**（-50%）
- 日常复习：**1 步**（-80%）

分阶段实施：Phase 0（1周，纯前端）→ 10步；Phase 1（1月）→ ≤5步；Phase 2（季度）→ ≤3步，结业率目标 >30%。

## 一、当前动线诊断

### 1.1 完整用户旅程图

| # | 步骤 | 决策成本 | 主要摩擦点 |
|---|------|:---:|------------|
| 1 | 课程页找到目标材料 | 1 | 材料列表无排序/筛选 |
| 2 | 点击材料 → 材料详情页 | 0 | — |
| 3 | 点击"进入工作台" | 1 | 用户需理解"工作台"概念 |
| 4 | 工作台加载 | 0 | — |
| 5 | **选择意图（学透/备考/复习）** | **3** | 三选一，新用户不确定哪个适合 |
| 6 | [learn/exam] 填写背景信息表单 | **2** | 自我评估熟悉度/考试日期 |
| 7 | 点击"开始分析" | 1 | 用户不清楚接下来会发生什么 |
| 8 | **等待管道处理（2-5分钟）** | 0（时间成本=5） | **最大流失节点** |
| 9 | 管道完成 → 学习计划预览 | 2 | 需理解每步并决定是否跳过 |
| 10 | 点击"确认并开始" | 1 | — |
| 11 | 模块卡片列表展示 | 1 | 手动选择从哪个模块开始 |
| 12 | 点击某个模块卡片 | 1 | — |
| 13 | 等待加载精讲内容（2-3秒） | 0 | — |
| 14 | 阅读精讲 Markdown | 0 | **核心学习环节** |
| 15 | [可选] 点击"自测验" | 1 | 需主动发现 |
| 16 | [可选] 点击"苏格拉底对话" | 1 | 需主动发现 |
| 17 | 返回模块列表 → 手动选下一模块 | 1 | **无自动导航，打断心流** |

**统计**：总步骤 17 · 用户决策点 8 · 等待节点 2（共约3-6分钟） · 可流失节点 5

### 1.2 最大摩擦点 TOP3

**① 2-5分钟管道等待（致命级）**
后端三阶段串行管道，用户只能看进度条。移动端用户极大概率切走后不回来。首次价值呈现延迟：5-8 分钟。

**② 意图选择 + 背景信息采集的认知门槛（高摩擦）**
在用户还没看到任何 AI 产出、尚未建立信任时，要求做出 8 项高认知成本的决策。更致命的是：代码审查发现这些数据**被完全丢弃**——`_data` 下划线前缀，`startDisassembly` body 只有 `material_id`，三种场景后端行为完全相同。

**③ 模块间手动导航（中高摩擦）**
学完一个模块后没有"下一步"按钮，没有自动推进，没有进度追踪。每次循环都有累积的放弃概率。

### 1.3 核心诊断

> **"工具箱心态"而非"体验心态"**：把 8 种工具、3 种意图、N 个模块的选择权全部交给用户，在建立信任前就要求做出高认知成本的决策。

## 二、用户场景拆分

### 2.1 三场景最短路径对比

| 维度 | 考前冲刺 | 深度学习 | 日常复习 |
|------|---------|---------|---------|
| 理想步骤数 | 2 | 3 | 2 |
| 最需要的单一功能 | 考点清单+薄弱标注 | 模块精读+苏格拉底问答 | FSRS 闪卡复习 |
| 最不需要的步骤 | Gathering + Plan Preview | Gathering familiarity | 整个 disassembly 管道 |
| 容忍等待时间 | ≤30s（焦虑状态） | 2-5min（可接受） | 0s（即开即用） |
| 当前实际步骤数 | 5 | 5 | 4（但走假流程） |
| 步骤膨胀率 | 2.5× | 1.67× | 2×（且毫无意义） |

### 2.2 三条关键代码发现

```typescript
// 1. API 不接受 intent 参数
body: JSON.stringify({ material_id: materialId })  // intent 完全未传

// 2. gathering 数据被丢弃（_data 下划线前缀 = 未使用）
const startProcessing = async (_data?: GatheringData) => { ... }

// 3. review 被映射为 learn
const intentForBackend = intent === 'review' ? 'learn' : intent
```

**结论：三种场景实际执行完全相同的管道——零差异化，这是架构而非 UI 的问题。**

### 2.3 场景特殊性

**考前冲刺**：整个 disassembly 管道对其有价值（Specialist 精讲 + Examiner 测验），但 gathering + plan-preview 是多余的。需要的是"直接出考点清单"而非"5步学习计划"。

**深度学习**：唯一合理需要 plan-preview 的场景——长期学习需要用户对计划有 ownership 感。这是智阶区别于 OpenMAIC 的核心差异化价值。

**日常复习**：根本不应进入 disassembly 管道。复习 = 基于已有知识的间隔重复，数据来源应是 FSRS 闪卡库，不是重新分析 PDF。当前是**假流程**。

## 三、竞品研究

### 3.1 OpenMAIC（清华，结业率 40%）

**用户旅程：2步到课堂**
```
上传 PDF → 等待约30分钟（异步，用户可离开）→ 进入互动课堂
```

**核心设计决策**：
- **零配置生成**：无需选择模式、难度、时长。AI 全权决定课程结构。
- **多角色社交模拟**：AI 老师 + AI 同学互动提问，制造"社交压力"，这是 40% 结业率的核心归因
- **等待与使用解耦**：~30 分钟异步生成，用户提交后可去做别的事，回来直接上课
- **L4 自动驾驶式课堂**：动态节奏（讲解/讨论/测验/模拟），防止走神

**对智阶的启示**：
1. 异步生成 + 先出先看：第一个模块完成即开始阅读，比 OpenMAIC 30 分钟体验更好
2. "一键开始"模式：高级选项折叠，只需确认一键开始
3. 智阶的个性化（BKT mastery + FSRS）是 OpenMAIC 没有的优势，应保持

**关键区别**：OpenMAIC 做"AI 课堂"（模拟授课场景），智阶做"AI 学习工作台"（个人化工具 + 记忆系统）。OpenMAIC 无个性化——所有学生看到相同课堂；智阶的差异化是 mastery 驱动的个性化路径。

### 3.2 Khanmigo（Khan Academy AI，3步/0决策点）

**用户旅程：3步到 AI 辅导**
```
登录 → 进入任意学习内容（视频/练习/文章）→ 点击 Khanmigo 图标 → AI 立即开始苏格拉底对话
```

**核心设计决策**：
- **零配置启动**：AI 根据用户当前所在页面（练习/视频/文章）自动判断辅导策略
- **意图推断 > 意图收集**：从用户行为推断意图，而非追问
- **AI 嵌入内容旁**：不是独立工具面板，而是每个学习页面的嵌入式辅助层
- **先价值后信息**：直接开始辅导，在对话过程中自然了解学生水平

**对智阶的启示**：
1. 上下文感知替代显式选择：用户打开材料时，AI 根据材料类型+用户历史自动推断意图
2. AIToolPanel 从"独立工具箱"转变为"嵌入式学习伴侣"

### 3.3 NotebookLM（Google，2步/0决策点）

**用户旅程：2步到洞察**
```
创建 Notebook → 上传文档 → 自动获得：Notebook Guide（摘要+关键主题+建议问题）+ Studio 面板
```

**核心设计决策**：
- **上传即开始**：文档上传后自动分析，无配置步骤
- **Studio 面板 5 个一键按钮**：FAQ / Study Guide / Timeline / Briefing Doc / Audio Overview
- **Audio Overview 成功原因**：零决策负担 + 新奇输出形式 + 被动学习模式 + 即时满足感

**对智阶的启示**：
1. 上传 PDF 后自动运行 Cartographer，生成"材料导览"作为第一触点
2. 至少一个"一键 wow 功能"：如"一键生成考前速查卡"或"一键生成学习播客"
3. AI 主动推荐下一步，而非等用户点按钮

### 3.4 竞品综合对比

| 维度 | OpenMAIC | Khanmigo | NotebookLM | 智阶当前 |
|------|---------|----------|------------|---------|
| 到第一有用输出的步骤 | 2步 | 2-3步 | 2-3步 | **8-17步** |
| 用户决策点 | 0 | 0-1 | 0 | **5-8个** |
| AI 角色 | 替用户做所有决策 | 上下文推断意图 | 自动分析推荐 | 等用户选工具 |
| 个性化 | 无（所有人相同） | 无（依赖课程树） | 无（文档级别） | **BKT + FSRS（最强）** |
| 核心结论 | 社交压力驱动结业 | 对话式嵌入 | 一键高价值输出 | **功能最强但动线最长** |

> **竞品核心启示**：智阶的问题不是功能不够，而是动线太长。竞品功能远不如智阶丰富，但赢在"2-3步到价值"。智阶需要的不是砍功能，而是**把 17 步压缩到 3 步，让强大的后端能力以"一键体验"的形式呈现**。

## 四、动线简化方案

### 4.1 核心策略：三路径分叉 + AI 先行

**原则**：让每条路径只走自己需要的最短流程；AI 替代低风险前置决策；高影响力决策保留给用户。

### 4.2 路径 A：考前冲刺（2步，当前5步，-60%）

```
[选"备考冲刺"] ──────────────────────────→ [考点速览 + 薄弱测验]
     ↓ AI 自动：                                    ↓
     - 跳过 gathering（数据本来就没用）        按优先级排序的模块
     - 跳过 plan-preview（焦虑用户不需要）     + 自动加载最高权重模块
     - 管道启动，第1个模块就绪立即展示         + 下一薄弱点按钮
```

**省略的步骤**：gathering 表单（数据被丢弃）+ plan-preview（焦虑用户不需要5步计划）

**前端改动（纯前端，P0）**：
- `handleIntentSelect('exam')` 跳过 gathering，直接调用 `startProcessing`
- 考前路径跳过 plan-preview，直接进入 complete 相位
- SSE `module_specialist_ready` 就绪时自动调用 `onModuleSelect`（第一个模块完成即展示）

**后端改动（P1）**：
- SSE 增加 `module_specialist_ready` 事件（某模块完成即推送，不等全部）
- `startDisassembly` 接受 `intent` 参数（可选，考前模式 Specialist 输出更精简）

### 4.3 路径 B：深度学习（3步，当前6步，-50%）

```
[选"学透"] ─→ [等待期间：进度+先看原文] ─→ [确认计划 → 自动连续学习]
     ↓               ↓                            ↓
  跳过 gathering   ProcessingView 加             保留 plan-preview
  （掌握度由      "先看原文"按钮              （深度学习需要 ownership）
   BKT自动推断）  + 预估时间 + 阶段总结       + 模块底部"下一模块"引导
```

**省略的步骤**：gathering 表单（familiarity 字段在代码中未使用）

**前端改动（纯前端，P0）**：
- `handleIntentSelect('learn')` 跳过 gathering，直接调用 `startProcessing`
- ProcessingView 增加"先看原文"按钮（切换到 original tab）

### 4.4 路径 C：日常复习（1步，当前5+步，-80%）

```
[选"快速复习"（或从首页/我的闪卡入口直接进入）]
     ↓ 完全绕过 disassembly 管道
     ├── 有到期闪卡 → 直接进入 FSRS ReviewSession
     ├── 有分析结果但无闪卡 → 自动从 Specialist + Quiz 生成闪卡 → ReviewSession
     └── 无分析结果 → "请先分析材料"（不走 disassembly！）
```

**省略的步骤**：整个 disassembly 管道（review → learn 映射是根本 bug）+ gathering + plan-preview

**前端改动（纯前端，P0）**：
- `handleIntentSelect('review')` 不调用 `startProcessing`，改为检查 localStorage 闪卡
- 新增 review 相位：内嵌轻量版 ReviewSession 或跳转 `/my/flashcards/:deckId/review`
- 闪卡自动生成：从 SpecialistOutput + QuizData 批量生成 FlashcardNote

**后端改动**：无！完全前端实现（FSRS + localStorage）

### 4.5 AI 决策分工

| # | 当前需用户决策 | AI 替代方案 | 实现难度 |
|---|--------------|------------|---------|
| 1 | 选意图（3选1） | 有考试日期→exam；无→learn；闪卡入口→review | 低（前端逻辑） |
| 2 | 填熟悉度 | BKT 默认 pL0=0.3，后续自动更新 | 低（删表单） |
| 3 | 确认学习计划 | 考前/复习跳过；深度学习保留 | 低（条件判断） |
| 4 | 选起始模块 | 按 exam_weight × (1-mastery) 自动推荐 | 中 |
| 5 | 决定何时做测验 | 精读完自动弹出"巩固测验？" | 中 |
| 6 | 选下一个模块 | 模块底部自动推进 + 键盘快捷键 | 低 |
| 7 | 决定是否生成闪卡 | 答错自动转闪卡；模块完成后批量生成 | 中 |

**必须保留用户决策**：学习意图最终确认（AI 推荐但可覆盖）、深度学习计划确认、考试日期设定

## 五、体验细节打磨

### 5.1 等待体验（触点1）

**改善方案**：
- 预估时间 + 倒计时：每阶段显示"约 45 秒"
- 阶段完成总结：节点完成时显示有信息量的文案（"识别出 6 个知识模块""生成 12,400 字精讲笔记"）
- 30秒后轮播"你知道吗"学科趣味知识（Linear 风格简洁文案）
- 增加"最小化"按钮，允许用户继续浏览 PDF，分析完成后 toast 通知

**微交互**：节点完成时 scale(0.8→1.0) 轻微弹入（120ms）；预估时间用 `tabular-nums` 等宽数字

### 5.2 错误处理（触点2）

**改善方案**：
- 错误分类：网络错误自动重试2次 / 单模块失败跳过继续 / 管道崩溃保留进度重试
- 部分降级：Specialist 完成但 Examiner 失败，仍展示精讲，Quiz 区域单独显示"重试"
- 人性化文案："分析引擎暂时繁忙" 而非技术错误码
- 已完成阶段保持 ✓ 状态，失败节点 ✗ + 局部重试

**微交互**：错误节点 shake 动画（±3px，2次，300ms）；自动重试显示 ↻ + "正在重试(1/2)"

### 5.3 学习完成成就感（触点3）

**改善方案**：
- 模块完成标记：`✓ 已学习`（accent-gold 色）+ 顶部进度条 `3/6 模块已学习`
- 测验高分庆祝：80%+ 标题变"出色的表现"，分数0→实际值计数动画（600ms ease-out）
- 100% 全对：细长 confetti 条纹（red-primary + accent-gold，1秒后消失）—— editorial 克制风格
- 连续学习里程碑：连续完成3个模块，短暂显示"连续学习了3个模块，保持这个节奏"

**原则**：庆祝应像论文被接收时的"Congratulations"，而非马戏团。

### 5.4 模块间过渡（触点4）

精讲内容底部追加导航区块：
```
─────────── 模块 3/6 完成 ───────────
下一模块：§4 应力-应变关系
[继续学习 →]    [做测验 ✎]
```

- 右侧当前模块高亮（`bg-bg-accent` + `border-l-accent-gold`）
- 键盘快捷键 `←` `→` 切换模块
- 滚动到底部 80% 时自动标记"已读"（IntersectionObserver）
- 模块切换 crossfade 过渡（150ms fade-out → 200ms fade-in）

### 5.5 Quiz 答错反馈（触点5）

**改善方案**：
- 答错后行动引导（延迟 500ms fade-in）：
  - `📖 查看精讲 §3.2` → 跳转对应模块
  - `🃏 加入闪卡` → 一键转为 FlashcardNote
- ScoreSummary 薄弱模块分析：按错误率排序的模块列表 + 跳转链接
- 答题实时统计：`5/8 已作答 · 正确率 60%`，低于 50% 时变 `text-red-primary`

## 六、体验设计原则（来自 Editorial Academic 设计系统）

**三条核心体验原则**：

1. **永远提供下一步（Never Leave a Dead End）**：任何状态终点（等待完成、错误发生、模块读完、测验答完）都必须给出明确的下一步行动选项。

2. **进度感知驱动信心（Progress Fuels Confidence）**：等待预估时间、模块完成比例、测验正确率——所有可量化进度对用户可见。数字和进度条比文字更有效地传递"我在前进"。

3. **克制的正反馈（Restrained Celebration）**：用精准文案、颜色变化（accent-gold）、微妙动画（checkmark draw、数字递增）替代夸张弹窗。

**视觉规范提示**：所有新增 UI 遵循 Editorial Academic——red-primary #A5192E、bg-main #F7F5F2、Instrument Serif 标题、Satoshi 正文、Borders over Shadows。

## 九、智阶的差异化护城河

竞品分析揭示了智阶当前被繁琐动线掩盖的核心优势：

| 能力 | OpenMAIC | Khanmigo | NotebookLM | 智阶 |
|------|---------|----------|------------|------|
| 深度教学流水线（逐页精讲+结构化测验） | ❌ | ❌ | ❌ | **✅** |
| FSRS 间隔重复 + AI 自进化闪卡 | ❌ | ❌ | 基础版 | **✅** |
| BKT mastery 驱动的个性化路径 | ❌ | ❌ | ❌ | **✅**（设计中） |
| 多学习意图适配（学透/备考/复习） | ❌ | ❌ | ❌ | **✅**（待实现差异化） |

**结论**：智阶的技术底座是三个竞品中最强的。Phase 0+1 的工作不是添加新能力，而是**移除挡在核心能力前面的摩擦层**，让已有的强大功能以"2-3步"的形式被用户感知到。
